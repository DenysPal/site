# 🔧 Правильна логіка логування page_code

## ❌ **Що було неправильно (виправлено)**

### Проблема:
- **Всі нові `page_code` автоматично призначалися** адміну `7855499159` (hexwizarsjsjbx)
- **Логи йшли НЕ тому, хто створив посилання**, а дефолтному адміну
- **Система створювала `page_code`** замість того, щоб шукати їх власників

### Наслідки:
- Користувач створює посилання з `page_code` "2-39"
- Коли хтось заходить на це посилання
- Лог йде адміну `7855499159`, а НЕ створювачу посилання

## ✅ **Як працює тепер (правильно)**

### 1. **Логування завжди відбувається**
- Кожен перегляд сторінки логується в `user_activity_logs`
- Незалежно від того, чи існує `page_code` в базі

### 2. **Повідомлення йдуть тільки власникам**
- Система **НЕ створює автоматично** нові `page_code`
- Шукає власника в таблицях `event_links` та `site_users`
- Якщо власник не знайдений → **повідомлення НЕ надсилається**

### 3. **Логіка пошуку власника:**
```python
# 1. Шукаємо в event_links (основна таблиця)
SELECT user_id FROM event_links WHERE event_code = '2-39'

# 2. Якщо не знайдено, шукаємо в site_users
SELECT tg_id FROM site_users WHERE page_code = '2-39'

# 3. Якщо не знайдено НІДЕ → повідомлення НЕ надсилається
```
