# План діагностики проблеми з втратою даних

## Поточна ситуація
Після застосування всіх попередніх виправлень (backup система, автоматичне відновлення, `last_page_code` логіка) проблема з втратою даних після 5+ циклів навігації все ще залишається.

## Аналіз проблеми
Проблема може бути в одному з наступних місць:
1. **Конфлікт між скриптами** - можливо, `stability-fixes.js` не завантажується правильно або конфліктує з іншими скриптами
2. **Проблеми з timing** - дані можуть очищатися занадто рано або пізно
3. **Проблеми з DOM** - елементи можуть не знаходитися або не оновлюватися правильно
4. **Проблеми з API** - можливо, API повертає помилки після певної кількості запитів
5. **Проблеми з браузером** - можливо, браузер очищає sessionStorage або має обмеження

## Інструменти діагностики

### 1. Python скрипт `debug_data_loss.py`
- Імітує цикли навігації
- Перевіряє стан даних після кожного циклу
- Генерує детальний звіт про втрати даних
- Запускається: `python debug_data_loss.py`

### 2. HTML монітор `debug_data_monitor.html`
- Показує стан даних в реальному часі
- Моніторить всі компоненти системи
- Логує всі події та помилки
- Відкривається в браузері

## План діагностики

### Крок 1: Запуск сервера та базової перевірки
```bash
python server_artpullse.py
```

### Крок 2: Запуск Python діагностики
```bash
python debug_data_loss.py
```
**Очікуваний результат**: Скрипт повинен показати, на якому саме циклі втрачаються дані та що саме втрачається.

### Крок 3: Відкриття HTML монітора
Відкрити `debug_data_monitor.html` в браузері та:
1. Запустити моніторинг
2. Виконати кілька циклів навігації вручну
3. Спостерігати за змінами стану в реальному часі

### Крок 4: Аналіз логів браузера
1. Відкрити Developer Tools (F12)
2. Перейти на вкладку Console
3. Виконати цикл навігації
4. Перевірити логи та помилки

### Крок 5: Перевірка sessionStorage
1. Відкрити Developer Tools (F12)
2. Перейти на вкладку Application > Storage > Session Storage
3. Виконати цикл навігації
4. Спостерігати за змінами в sessionStorage

## Що шукати

### В Python діагностиці:
- На якому циклі втрачаються дані
- Які саме дані втрачаються (сторінка, API, кеш)
- Чи є помилки HTTP або API

### В HTML моніторі:
- Зміни стану карток (зелена → жовта → червона)
- Логи подій та помилок
- Зміни в поточних даних

### В логах браузера:
- Помилки JavaScript
- Попередження про завантаження скриптів
- Помилки API запитів

### В sessionStorage:
- Коли з'являються/зникають ключі
- Чи створюються backup дані
- Чи зберігається `last_page_code`

## Можливі причини та рішення

### 1. Конфлікт скриптів
**Симптоми**: `stabilityFixes` недоступний, помилки JavaScript
**Рішення**: Перевірити порядок завантаження скриптів, усунути конфлікти

### 2. Проблеми з timing
**Симптоми**: Дані очищаються занадто рано/пізно
**Рішення**: Налаштувати затримки, покращити логіку очищення

### 3. Проблеми з DOM
**Симптоми**: Елементи не знаходяться, дані не оновлюються
**Рішення**: Перевірити селектори, додати перевірки існування елементів

### 4. Проблеми з API
**Симптоми**: API повертає помилки, дані не завантажуються
**Рішення**: Перевірити серверні логи, додати retry логіку

### 5. Проблеми з браузером
**Симптоми**: sessionStorage очищається неочікувано
**Рішення**: Додати localStorage як backup, перевірити обмеження браузера

- sessionStorage повинен правильно зберігати та відновлювати дані
