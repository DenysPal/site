# Стабільна Система Управління Даними для Виставок

## Опис Проблеми

Раніше при навігації між сторінками виставок (захід на виставку → кнопка "Home" → знову захід на виставку) дані збивалися через:

- Дублювання скриптів
- Конфлікти в `sessionStorage`
- Втрату `page_code` при навігації
- Відсутність кешування даних
- Нестабільну обробку помилок API

## Рішення

Створена стабільна система управління даними `EventDataManager`, яка:

✅ **Запобігає збитку даних** при навігації  
✅ **Автоматично кешує** дані з API  
✅ **Синхронізує** `page_code` між сторінками  
✅ **Захищає від дублювання** ініціалізації  
✅ **Обробляє помилки** з fallback на кеш  
✅ **Очищає застарілі дані** автоматично

## Використання

### 1. Підключення Бібліотеки

```html
<script src="/js/event-data-manager.js"></script>
```

### 2. Створення Менеджера Події

```javascript
// Автоматичне створення
const manager = createEventDataManager({
  index: 1,                    // Індекс події в API
  name: 'Collection Co–selection', // Назва події
  defaultDuration: '3 hours'   // Тривалість за замовчуванням
});

// Або ручне створення
const manager = new EventDataManager({
  index: 6,
  name: 'Uncensored',
  apiEndpoint: '/api/custom_endpoint'
});
```

## Функціональність

### Автоматичне Керування Даними

- **Завантаження**: Автоматичне отримання даних з API
- **Кешування**: Збереження даних на 5 хвилин
- **Fallback**: Використання кешу при помилках API
- **Очищення**: Автоматичне видалення застарілих даних

### Синхронізація Навігації

- **URL Tracking**: Відстеження змін в URL
- **Link Updates**: Автоматичне додавання `page_code` до посилань
- **Menu Sync**: Синхронізація посилань в меню
- **Buy Button**: Оновлення кнопки покупки квитка

### Захист від Помилок

- **Duplicate Prevention**: Захист від повторної ініціалізації
- **Error Handling**: Graceful обробка помилок API
- **Data Validation**: Перевірка цілісності даних
- **Cache Recovery**: Відновлення з кешу при збоях

## API Методи

### Основні Методи

```javascript
// Отримання поточного page_code
const pageCode = manager.getPageCode();

// Отримання даних події
const eventData = manager.getEventData();

// Примусове оновлення даних
manager.refresh();

// Очищення кешу
manager.clearStaleData();
```

### Статичні Методи

```javascript
// Отримання екземпляра за назвою
const manager = EventDataManager.getInstance('collection_co_selection');

// Отримання всіх активних екземплярів
const instances = EventDataManager.getAllInstances();

// Очищення всіх кешів
EventDataManager.clearAllCaches();
```

## Система Подій

```javascript
// Слухання оновлення даних
window.addEventListener('eventDataManager:dataUpdated', (e) => {
  console.log('Дані оновлено:', e.detail.data);
  console.log('Менеджер:', e.detail.manager);
});

// Слухання помилок
window.addEventListener('eventDataManager:error', (e) => {
  console.error('Помилка:', e.detail.error);
});
```

## Кешування

### Структура Кешу

```javascript
{
  "event_data_PAGE123_1": {
    "data": { /* дані з API */ },
    "timestamp": 1640995200000,
    "version": "1.0"
  }
}
```

### Політика Кешування

- **Термін дії**: 5 хвилин для активних даних
- **Автоочищення**: 1 година для застарілих даних
- **Версіонування**: Підтримка різних версій кешу
- **Селективне очищення**: Видалення тільки застарілих даних

## Переваги Нової Системи

### Стабільність
- ❌ **Раніше**: Дані збивалися при навігації
- ✅ **Тепер**: Дані залишаються стабільними

### Продуктивність
- ❌ **Раніше**: Повторні запити до API
- ✅ **Тепер**: Кешування та оптимізація

### Надійність
- ❌ **Раніше**: Втрата даних при помилках
- ✅ **Тепер**: Fallback на кеш та обробка помилок

### Зручність
- ❌ **Раніше**: Ручне керування посиланнями
- ✅ **Тепер**: Автоматичне оновлення всіх посилань

## Тестування

### Сценарій 1: Навігація Між Сторінками
1. Зайти на виставку з `page_code=PAGE123`
2. Перейти на головну сторінку (кнопка "Home")
3. Знову зайти на виставку
4. **Очікуваний результат**: Дані завантажуються з кешу, `page_code` зберігається

### Сценарій 2: Оновлення Даних
1. Зачекати 5+ хвилин
2. Оновити сторінку
3. **Очікуваний результат**: Нові дані завантажуються з API

### Сценарій 3: Обробка Помилок
1. Симулювати помилку API (відключити мережу)
2. **Очікуваний результат**: Дані завантажуються з кешу або встановлюються значення за замовчуванням

## Підтримка

### Вимоги
- **Браузери**: IE11+, Chrome 60+, Firefox 55+, Safari 12+
- **JavaScript**: ES6+ (async/await, classes, arrow functions)
- **API**: Fetch API

### Обмеження
- Кеш зберігається тільки в `sessionStorage`
- Дані не синхронізуються між вкладками
- Максимальний розмір кешу: ~5-10MB

## Майбутні Покращення

- [ ] Синхронізація між вкладками через `BroadcastChannel`
- [ ] Індексировання кешу для швидкого пошуку
- [ ] Адаптивне кешування залежно від трафіку
- [ ] Метрики продуктивності та аналітика
- [ ] Підтримка offline режиму

## Висновок

Нова система `EventDataManager` забезпечує:

1. **Стабільність** даних при навігації
2. **Швидкість** завантаження через кешування  
3. **Надійність** через обробку помилок
4. **Зручність** через автоматизацію

Тепер користувачі можуть вільно навігувати між сторінками без втрати даних, а система автоматично підтримує цілісність та актуальність інформації.
