# 🔧 Вирішення проблеми "address already in use"

## ❌ Проблема
При запуску бота виникає помилка:
```
OSError: [Errno 98] error while attempting to bind on address ('0.0.0.0', 8081): address already in use
```

## 🔍 Причини
- Порт 8081 вже використовується іншим процесом
- Попередній запуск бота не був коректно завершений
- Інші сервіси використовують цей порт

## ✅ Рішення

### 🚀 Швидке рішення (рекомендовано)
```bash
python quick_start.py
```
**Що робить:**
- Автоматично знаходить вільний порт
- Запускає бота на вільному порту
- Не потребує додаткових дій

### 🔍 Діагностика проблеми
```bash
python check_ports.py
```
**Що показує:**
- Які порти зайняті
- Які процеси використовують порти
- Можливість завершити процеси

### 🛠️ Розширене рішення
```bash
python start_bot.py
```
**Що робить:**
- Повна перевірка системи
- Автоматичне очищення портів
- Детальна діагностика

## 🔧 Ручне очищення портів

### Linux/Mac:
```bash
# Знайти процес на порту 8081
sudo netstat -tlnp | grep :8081

# Завершити процес
sudo kill -9 <PID>
```

### Windows:
```cmd
# Знайти процес на порту 8081
netstat -ano | findstr :8081

# Завершити процес
taskkill /PID <PID> /F
```

## 🎯 Альтернативні порти

Якщо потрібно використовувати конкретний порт:

### Варіант 1: Зміна в коді
```python
# В main.py змініть порт
site = web.TCPSite(runner, '0.0.0.0', 8082)  # замість 8081
```

### Варіант 2: Змінна середовища
```bash
export WEBHOOK_PORT=8082
python main.py
```

## 🚨 Важливі зауваження

### ✅ Рекомендується:
- Використовувати `quick_start.py` для автоматичного запуску
- Перевіряти порти перед запуском
- Закривати бота коректно (Ctrl+C)

### ❌ Не рекомендується:
- Примусово завершувати процеси без діагностики
- Використовувати занадто високі порти (>9000)
- Запускати кілька екземплярів бота одночасно

## 🔄 Автоматичне вирішення

Система автоматично:
1. **Шукає вільний порт** у діапазоні 8081-8100
2. **Використовує перший вільний** порт
3. **Повідомляє** про використаний порт
4. **Зберігає порт** у глобальній змінній
